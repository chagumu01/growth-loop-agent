# 成长回路功能规划与验收方案

日期：2026-10-25
状态：待确认；确认后进入实现阶段。

## 1. 目标与范围

将现有学习与行动记录产品完善为能够执行任务、检索个人学习记忆，并通过自动评测验证效果的 Agent。方案围绕三个方向：受控工具执行、可追溯学习记忆、自动评测与运行观测。

本轮仅整理方案，不修改业务代码。以下为拟定设计，不代表功能已实现。

## 2. 当前基础

项目使用 Next.js、React 和 TypeScript，已有 AI 对话、行动计划展示、学习课程、理解测验、晚间回顾及 Android 入口。相关接口包括 `/api/agent`、`/api/quiz` 和 `/api/learning-program`。

记录及课程进度部分依赖浏览器 localStorage，演示数据使用固定种子。当前尚未具备本方案需要的统一持久化数据层、可靠工具执行记录、跨用户检索隔离与系统化评测链路。这些判断来自项目说明及源码检查，尚未进行运行验收。

## 3. 受控任务执行

### 3.1 用户流程

用户发送“把明天的复习安排好”等请求后，Agent 提取意图及结构化参数。信息不足时追问；参数有效时生成待确认操作卡，显示操作类型、内容、日期及影响。用户确认后由服务端执行，最后返回真实执行结果和记录入口。

查询计划等只读操作可直接执行。创建、修改和删除数据的操作必须经过用户确认；确认后参数发生变化，应重新确认。取消或过期的操作不得执行。

### 3.2 工具范围

| 工具 | 作用 | 关键校验 |
| --- | --- | --- |
| 创建任务 | 将行动加入计划 | 标题、日期、分类及用户归属 |
| 查询计划 | 查询本人指定日期的任务 | 日期范围和访问权限 |
| 保存学习记录 | 保存学习内容与来源 | 内容、来源、用户归属 |
| 安排复习 | 根据学习记录生成复习任务 | 原记录访问权限、复习时间和重复安排 |

模型仅提出工具调用及参数；服务端负责鉴权、参数校验、确认校验和实际写入。不得直接信任模型提供的用户身份。

### 3.3 状态与恢复

操作状态至少覆盖：待确认、已取消、已过期、执行中、成功、失败和结果待核实。保存操作参数、确认版本、幂等键、执行结果、错误类别及尝试次数。

同一确认操作的重复点击和网络重试使用同一幂等键；同一用户明确发起的新操作使用新的键。幂等约束与业务写入须在事务中保持一致，避免重复任务、重复积分和状态失真。

输入错误及权限错误不自动重试。短暂网络故障可限次重试；超时但无法确定写入结果时，先依据操作记录核实结果，再决定是否重试。服务重启后可以恢复未完成状态，并向用户展示后续处理入口。

### 3.4 验收标准

- 写操作在确认前不改变业务数据，取消后不执行。
- 缺少必填参数时能够追问，非法参数不会写入。
- 同一操作重复点击、并发提交或超时重试只产生一次业务效果。
- 执行失败显示可理解原因；恢复执行不会重复创建任务或计分。
- 查询与写入均受用户归属约束，伪造身份参数不能访问他人数据。

## 4. 可追溯学习记忆与检索

### 4.1 用户流程

用户保存学习笔记、测验反馈或项目成果后，系统建立可检索的学习记忆。用户提问“我之前学过什么”或“哪些知识点还没有掌握”时，Agent 检索本人记录，生成带来源引用的回答。

未检索到足够证据时说明信息不足。“未掌握”的判断应引用实际测验反馈或学习记录，不能仅凭模型猜测。

### 4.2 数据与索引

拟建立用户、学习记录、测验反馈、成果、知识片段和索引任务等实体。每条原记录保留用户归属、来源、创建与更新时间及内容版本；片段关联原记录与版本。

按知识点或语义段落切分，保留必要上下文；片段长度、重叠量及召回数量通过评测确定。候选检索采用关键词与向量召回，合并去重后按相关性筛选；重排是否接入由质量与延迟对比决定。

访问控制必须在关键词检索、向量检索及引用读取各阶段生效。用户身份从可信会话获取，不依赖请求正文中的用户 ID。

### 4.3 更新、删除与引用

笔记更新后生成新版本并更新索引；检索结果需校验有效版本，避免旧内容继续参与回答。删除时立即禁止检索和引用访问，再清理片段、向量及相关缓存。索引任务可重试并有失败记录。

回答中的引用关联原始记录，用户可打开查看来源及时间。无法访问或已经删除的来源不能被继续引用。检索到的笔记属于资料，不得作为改变系统规则或调用工具的指令。

### 4.4 验收标准

- 关键词、同义表达及跨记录问题能够召回相关来源。
- 每个引用可定位到本人有效的原始记录，结论与引用内容一致。
- 无相关记录时明确提示证据不足。
- 更新后不再使用旧版本；删除成功后立即无法检索和打开原记录。
- 不同账号及恶意构造请求不能召回或引用其他用户内容。
- 索引失败可观测并可恢复，不把“已保存”误报为“已完成索引”。

## 5. 自动评测与运行观测

### 5.1 场景集

建立固定、可重复运行的场景集，覆盖行动记录、计划查询、复习安排、模糊表达、错误输入、确认与取消、重复点击、工具超时、检索无结果、更新删除及跨用户访问。

每条用例包含初始数据、输入、预期意图、关键参数、允许操作和预期业务状态。优先使用合成或脱敏数据；真实个人记录经授权后方可纳入。

### 5.2 评测层次

| 层次 | 评测内容 | 判断依据 |
| --- | --- | --- |
| 意图识别 | 是否正确区分记录、查询、计划和复习 | 标注场景与预期意图 |
| 参数提取 | 日期、内容及关联记录是否正确 | 必填字段与归一化参数 |
| 工具执行 | 确认、鉴权、幂等及恢复是否正确 | 执行记录和最终数据状态 |
| 检索质量 | 是否找到相关有效记录 | 标注来源、Recall@K、引用正确性 |
| 最终完成 | 是否真实完成用户目标 | 最终业务状态及回答一致性 |

规则断言用于权限、状态和副作用检查；开放回答可使用人工抽检及模型辅助评价，模型评分不作为唯一依据。

### 5.3 运行观测与版本比较

通过统一请求标识串联模型请求、检索、确认和工具执行。采集总耗时、各阶段耗时、模型及提示词版本、检索配置、工具结果、重试次数、失败类别，以及供应商实际返回的 Token 用量。

供应商未提供 Token 数据时标为未知；费用估算注明模型价格和估算依据。日志默认不保存密钥或完整个人学习内容。

在同一评测集与初始数据上比较不同提示词、模型和检索策略，输出质量、延迟及成本差异。固定用例接入回归检查；初始基线跑出后再确认数值门槛，不预设没有依据的质量承诺。

### 5.4 验收标准

- 评测可用单条命令运行，并给出通过情况、失败明细和版本信息。
- 未确认写入、越权访问和重复副作用等关键用例必须全部通过。
- 每次失败能够定位到具体阶段和错误类别。
- 同一用例可在隔离测试数据上重复运行，不污染日常学习记录。
- 模型或提示词变更后可查看与基线的差异，关键回归失败时阻止交付。

## 6. 技术组织与数据基础

建议保留现有 Next.js 页面和接口入口，将业务能力拆为工具执行服务、学习记忆服务、检索服务与评测观测模块，逐步从页面内状态迁移到受控服务端。

拟采用关系型数据库保存任务、记录、确认与执行状态；可优先评估 PostgreSQL 及 pgvector，以统一事务和检索元数据管理。具体数据库、模型供应商和部署方式在实施前依据现有运行环境确定，不在本轮引入新的云服务或付费资源。

真实用户会话及用户隔离是多用户验收的前置条件。旧 localStorage 数据应提供明确的迁移流程，迁移以原记录标识去重；演示数据与用户正式数据分开处理。

拟修改范围包括现有对话接口及页面、学习与测验数据接入，以及新增服务模块、数据库结构和评测脚本。详细路径以实际实现设计为准。

## 7. 实施顺序

| 阶段 | 工作内容 | 完成条件 |
| --- | --- | --- |
| 第一阶段 | 建立评测骨架、数据模型、会话归属与执行记录 | 现有行为有基线，数据可持久化并隔离 |
| 第二阶段 | 接入四类工具、确认卡、幂等与失败恢复 | 任务执行关键验收全部通过 |
| 第三阶段 | 接入学习记忆、混合检索、引用及更新删除 | 检索、引用和隔离验收通过 |
| 第四阶段 | 完善端到端评测、观测与版本对比 | 可重复回归并查看效果和成本差异 |

评测从第一阶段开始，随后随功能增量补齐。每阶段完成后展示可验证的操作流程与检查结果。

## 8. 交付与确认范围

交付内容为可运行功能、必要的数据迁移、评测脚本与结果，以及运行配置说明。界面延续现有视觉风格，并检查电脑与手机端主要流程；涉及 Android 容器能力时增加对应联调。

实现阶段执行类型检查、代码检查、构建和关键流程验证。微信主动提醒、正式 Android 发布、社交功能及付费能力不纳入本次范围；安排复习首先表示创建复习任务，不默认承诺后台通知。

本方案建议三个方向全部纳入，按上述阶段实施。确认本方案仅代表允许进入功能实现；外部服务选型及涉及费用的操作另按实际需求确定。
